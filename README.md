# 臺中公車捷運即時路線圖

以捷運路線圖風格呈現臺中市主要公車路廊與捷運綠線，並提供全市公車站位／路線查詢。資料來自交通部 TDX 運輸資料流通服務。

**線上展示**：部署後網址為 `https://<帳號>.github.io/Schematic-Transit-Taichung/`

## 功能

### 路線圖（`taichung.html`）
- 規劃捷運路網風格（參考臺北捷運路網圖）：每條規劃路線用目前行經該路廊的高頻公車呈現即時車輛與到站時間
  - 綠線：營運中＋東延大坑（東山路公車）、南延彰化（101 等）
  - 藍線：臺中港─臺灣大道（300 系列）─臺中車站─建成路─太平─東平
  - 橘線：臺中機場─中清路─水湳─中友／臺中科大─雙十路─臺中車站─國光路─中興路─霧峰（500、200 等）
  - 紅線：豐原轉運中心─西勢路／承德路─崇德路─三民錦新（700 等）
  - 紫線（屯區環狀）：大慶─高工路─大里─仁化─太平─東平─坪林─大坑（73、3、51 等）
  - 預留（虛線）：紅線延伸五權路／五權西路、黃線豐科線、青線科工線
- 保留市中心其他公車路廊（北屯─三民、西屯路、公益路、英才、健行─美村、忠明南、漢口─東興、河南路、黎明路、民權路）以細線表示
- 只畫轉乘站、端點與重點站，小站只用來推算車輛位置；規劃路線端點有路線代號方塊；所有線段只有水平、垂直與 45°
- 手機直式優先：開啟時放大到市中心，↺ 看全圖；🚌 開關即時車輛（關閉時不在背景更新全部站牌）
- 點公車或路線：面板顯示與查詢頁相同的整條路線各站即時／時刻表／班次狀態；地圖只畫選定方向，沿實際站序連續畫出（不在圖上的路段以虛線連接），箭頭標示方向、終點標示去向
- 版面與路線資料由 `node tools/mk_plan.js` 產生（讀 `taichung-legacy.html` 舊路廊資料與 `taichung-network.js`）；舊版路線圖保留為 `taichung-legacy.html`
- 公車位置依即時預估到站時間推算；點路廊展開各路線的平行線
- 點站牌：依行車方向分欄的到站卡片、與每日營運時刻表比較早到／晚到
- 點路線：整條路線各站即時資料與全日時刻表
- 行程規劃：選起訖站，列出直達或轉乘 1～2 次的方案；上車時間只採用 API 提供的時刻

### 查詢（`taichung-query.html`）
- 「📍 附近」（站位、路線清單）：定位點在畫面中以我的位置搜尋；否則以地圖中心 500 公尺內搜尋，地圖上以藍色圖釘與半徑圈標示
- 捷運綠線、藍線路廊頁的「📍 附近」同公車路線頁：持續追蹤最近車站（綠線展開該站全日時刻表、藍線打開車站視窗的最近兩班），再按停止
- 全市站位 → 站牌（依行車方向分組）各路線的即時到站與時刻表；今日各站牌內依到站時間排列：即時預估 → 尚未發車（灰字「HH:MM 發車」）→ 末班車已過／今日未營運，顯示方式與路線圖頁相同
- 附近 YouBike：0 車可借以橘色、0 位可還以深紅色標示
- 全市公車路線的即時資訊、未來 7 日各站時刻表、公車即時位置
- 捷運綠線路線簡圖、實際線形與車站位置、依班距推算的各站時刻表
- 地圖可持續顯示自己的位置
- 即時到站在 15 分鐘內顯示倒數（分秒），超過 15 分鐘改顯示預估到站時刻 HH:MM
- 下一班過了表定發車時間 10 分鐘仍沒有車發出（要先按「比對準點／遲發」載入車輛班次），標示「未依時刻表發車」；依回站車輛推估的「預估延遲發車」在能把班次對應到車牌前暫停顯示
- 路線清單「藍線」群組：一鍵把規劃捷運藍線沿線的公車路線載入多選（藍線兩側 300 公尺內、沿線重疊 3 公里以上的子路線，依路線號碼排序），地圖同時畫出藍線
- 多選中的捷運藍線路廊與綠線也分方向（⇄ 切換，同多選公車）：藍線路廊只顯示往臺中車站或臺中港、且在路廊範圍內的公車位置（不畫路線線形），車站視窗顯示該方向最近兩班；綠線只顯示該方向的推估列車；線上箭頭標示方向
- 多選路線的公車位置合併查詢：2～25 條一次查詢（以 RouteUID 串接），超過 25 條改抓全市一次，每次更新只用 1 次 API
- 標題列右側：捷運風格路線圖、外觀切換（月亮＝深色、太陽＝淺色）、地圖圖層；手機上圖層卡片與標題列同寬，右上 × 關閉

### 站站時刻表的來源
中途站的時刻只用以下兩種，沒有就顯示「本站無預估班表」（起站仍列發車時刻），不用直線距離或即時預估去推估：
- 發車時刻（路線班表／每日營運時刻表）＋TDX 站間旅行時間
- 站站推估班表（V3，近 3 個月歷史）或 TDX 時刻表本身給的各站時刻

班距發車的路線（例 35）路線班表只有班距，TDX 每日營運時刻表也只有今日。查未來日時：
- 此裝置曾查過同星期（或班距設定相同）的日子、35 天內 → 以那天的每日營運時刻表發車時刻當參考，標「參考 MM/DD（週?）…實際以當日為準」；只存發車時刻，不多用 API
- 沒有參考 → 只顯示當日班距

### 路徑規劃（查詢頁「規劃」）
- 上下車時刻只用：即時預估到站（標「即時」），或路線班表＋站間旅行時間（標「表定」）
- 沒有站間旅行時間的路線，只能搭即時預估中有到站時刻的車，下車時刻用同一台車的預估；起點附近有這類路線的車時，另查該路線即時（最多 3 條）。未來日期不會排入這類路線
- 已載入路線即時的段落都用即時判斷誤點、早到、末班已過
- 選取方案時查各轉乘路線即時；停駛、車已過站、晚到 5 分以上或原預估的車已不在即時資料中，就從前一段下車站重新規劃（排除接不上的路線），立即列出最多 2 個第一段路線不同的當下可行替代方案，可一鍵改用
- 起訖輸入框可搜尋公車站位、地標／店名（OpenStreetMap，約 2 萬個地點，附類別與行政區）與 YouBike 站（站名或地址）；不分大小寫、台／臺通用；輸入框空白時列出最近選過的 8 個站；手機點輸入框時抽屜上移一級，鍵盤不擋搜尋結果
- 3D 導航中持續檢查：要搭的車末班已過／停駛、要等超過 20 分或尚未發車；下一個轉乘依我這台車到下車站的即時預估＋步行，判斷接不上、轉乘緊湊（< 1.5 分）、等候超過 15 分；YouBike 借車站無車、還車站無位。有狀況顯示 ⚠️ 並列出最多 2 個其他抵達終點的方案，可一鍵改用（轉乘狀況保留目前這段，只換後面）
- 導航看板：同站轉乘合成一張（前段 hh:mm下車 → 同站轉乘 → 下一段）；下車圖釘標 hh:mm下車，之後的轉乘段標 hh:mm轉乘上車（時間軸同步顯示）
- 導航時間軸：左側路線色軸把上車站圓圈、搭乘線、下車站圓圈連成一條；同站同側轉乘畫雙色同心圓（內圈前段車、外圈下段車），同站名對向轉乘兩站圓圈分開、中間 ⇄「對向轉乘」
- 導航時刻都標來源：表定（時刻表）／推估（班距、上車時刻＋規劃車程）／即時（動態 API）；起點站「HH:MM 發車」，中間站「mm分ss秒 到站／進站中」
- 本站沒有即時到站（尚未發車）時，依今日班表找下一班並配對車輛：標「已發車」（遲/早 N 分）或「未依時刻表發車」（遲 N 分），後面接「下一班 HH:MM／mm分ss秒 到站」（起點站為 HH:MM 發車）；轉乘段同理
- 導航帶入路徑規劃查到的上車／下車時刻，開始時即時資料還沒回來也有時間；之後各轉乘段依前段下車時刻（即時→推估→規劃）＋步行逐段推算接得上的班次，不再顯示「前段到站後再確認」
- 導航公車位置：搭乘中以手機定位為主（定位 10 秒內、精度 ≤ 60 m、在路線 60 m 內；只往前，倒退 < 150 m 視為飄移），API 公車位置只用來確認車牌與塞車，更新改 90 秒；離站時自動鎖定手機旁的那台車，鎖錯（與手機差 > 600 m 超過 60 秒）且附近有另一台時自動改鎖；剩餘站數也以手機為準
- 其他公車（候車、轉乘）新資料進來時柔性修正：落後就加速（最多約 1.5 倍）、超前就放慢到 20%～100%（不停、不倒退），約 20 秒收斂；差超過 500 m 才直接跳
- 可能搭上了別台車：不符合自動上車、但手機時速 ≥ 18 km/h 連續 45 秒時，用最近 2 分鐘軌跡比對沿線路線（不耗 API）、再合併查一次候選路線公車位置對到車號（附近沒有公車＝不提示；多台分不出時 75 秒後再查，仍分不出就列出讓使用者選）。確認後列出「繼續搭到 X 站 hh:mm 下車，步行到目的地（≤ 500 m）或再轉乘」與「下一站／再下一站下車改搭 Y」，標建議，一鍵改用
- 手機版站位／路線／規劃調整抽屜高度時，地圖平移讓原本畫面中心維持在可見範圍中間。定位藍點（第一次定位、跟隨、羅盤模式）與「附近」追蹤的最近站也放在標題列與抽屜之間可見地圖的正中間。
- 規劃不用按鈕：起訖、出發模式、時間（停 0.7 秒）、日期、YouBike 一改就自動重新規劃。規劃模式右下的附近／地圖／搜尋換成「⚡ 立即出發」（有方案才顯示），目前選取的方案直接開始導航；方案卡的「🧭 開始導航」先進預覽：預覽是等車畫面（上方卡：要搭的路線、(車牌)、還有幾站、幾分到上車站；地圖北朝上、不傾斜，要搭的車、上車站、轉乘點、終點都放在上方卡與抽屜之間；終點只顯示 🏁，點了才出站名），公車位置與到站依候車階段的間隔更新、用導航同一套平順位置；「開始導航」倒數 5 秒沒按就自動開始，捲動抽屜或拖地圖就停止倒數；「離開」關閉預覽
- 路徑規劃「全日時刻表」：一整天每種搭法（路線組合＋上下車站）的第一段上車時刻，格式同站站時刻表，分鐘數字下方小字寫上車站第一個字（匯出圖也有）；顏色＝搭車時間（第一段上車到抵達，含轉乘等車與最後步行），本次查詢最短綠、最長紅、中間黃，下方色條標分鐘範圍；直達加粗加底線。頁籤：全部（同一上車時刻只留最快）／直達／轉乘 1 次／轉乘 2 次以上／⭐ 常用，去掉「比另一班早上車卻更晚到」的班次。只用班表，不打 API；從 00:00 起算，含凌晨夜間公車（例 326；夜間公車的路線號碼旁加 🌙＝凌晨 00～04 點有 2 個以上不同時刻發車）。現在出發／指定時間在 21:00 後也會接著找隔天凌晨的班次（標「隔天凌晨」）
  - 點時刻看完整方案（同規劃結果，可開始導航）；📅 加入行事曆（手機直接跳到行事曆新增活動畫面：Android 開系統行事曆，沒有行事曆 App 時開 Google 日曆新增頁，提醒用行事曆預設值；iOS Safari 跳出「加入行事曆」，含出門前 15 分提醒；其他瀏覽器用分享面板或下載 .ics；依班表不隨即時誤點更新）；☆ 加入常用（起訖＋路線組合，存在裝置、最多 10 組），規劃頁上方一鍵帶入，現在出發／指定時間時常用組合的下一班排最上面；也可只把起訖加入常用（☆ 加入常用，不指定路線，點選後照常規劃），與路線組合共用 10 組上限；常用清單收成一行左右滑，每組可點 emoji 自訂；最前面「🏠 回家」「🏢 上班上課」：第一次按先設定位置（搜尋站名或地圖點選，存在裝置；長按修改），之後按下就從目前位置規劃過去
  - 匯出：一週各天依相關路線班表分組（相同就合併、不同就分開），每組全部頁籤 → PNG（手機直式 1080×2340）或 A4 PDF，直接下載檔案
- 導航（預覽與導航中）時刻不重複：站名行標 hh:mm上車／下車，第二行只放發車狀態、早遲、15 分內倒數；同站轉乘看板改「前段 hh:mm下車 ↓ 同站轉乘 下一段」；點路線方塊看該路線查詢資訊（標示上車站），上方「🧭 回到導航」返回
- 單循環／只有一端發車的路線（如 45、555，全市 21 個子路線方向）：回程沒有發車時刻時，回程第 k 班＝去程第 k 班抵達端點＋端點間移動（60 m 內視為同站；否則直線×1.3 以 15 km/h 估），各站再加行駛時間——歷史 V3（只用裝置快取，不呼叫 API）優先，其次 TDX 站間旅行時間；標「推估」並註明非實際發車時刻。今日每日營運時刻表已有該方向時照用；路徑規劃同樣套用
- 今日發車異常（標題列 ⚠️、監測路線的路線頁）：監測 45、51、35、23、19、326（含 45延、45區、45延1、51副）
  - GitHub Actions（`.github/workflows/dispatch-watch.yml`＋`tools/watch_dispatch.js`）每 15 分鐘只記錄實際發車：A2 以 OData 過濾監測路線且 TripStartTime 在上次抓取後的車（每次 1 次 API，回應通常幾十 bytes），寫到 `data` 分支 `departures/YYYY-MM-DD/<路線>.csv`（欄位 plate,sub,dir,start,stop,seen,type,seq,ev,bus,duty：stop/seen＝第一次抓到這一趟時的站與 GPS 時間；type＝TripStartTimeType，TDX 定義 0 實際發車時間、1 預估發車時間、2 無法推估（start 空白）；seq/ev/bus/duty＝StopSequence、A2EventType、BusStatus、DutyStatus。也抓無法推估發車時間的車（同車牌同方向 150 分內只記一次），BusStatus 99 非營運、DutyStatus 2 已到終點結束的車不記），抓取時間記在 `_polls.txt`；發車時刻依 TripStartTimeType 處理：0 實際發車只在不可能成立時才推翻，1 TDX 預估照位置規則可被推翻並標「TDX 預估發車」，2 只靠位置反推；起點站離站事件直接當發車時刻；站序對得上就用站序定位（站名重複也能推）。司機發車時刻按錯的修正：依「車在哪站＋GPS 時間 − 時刻表起點到該站分鐘」反推發車，與回報差 10 分以上（只用離起點 15 分內的位置；較遠的只標疑似，避免把途中塞車當晚發）或回報晚於車已在途中時改用反推（標「依位置推算；車機回報 HH:MM」），反推不可靠或推不出來仍列異常但標「疑似」；車機沒回報本趟發車時刻（TripStartTime 空值）或回報的是之前班次的舊值時，線上車改用位置反推配對（標疑似）；車輛資訊只顯示這台車正在跑的這一趟；有車在線但沒回報發車時刻時，漏班仍列出但標疑似；需在 repo Secrets 設 `TDX_CLIENT_ID`、`TDX_CLIENT_SECRET`；GitHub 排程不準時或不跑時，可改用外部排程觸發 workflow_dispatch：
    - GitHub fine-grained PAT：只選這個 repo，Repository permissions 只開 Actions: Read and write（權杖只放在外部排程服務，不進 repo）
    - 外部排程（例 cron-job.org）每 15 分鐘 `POST https://api.github.com/repos/<owner>/<repo>/actions/workflows/dispatch-watch.yml/dispatches`，Header `Authorization: Bearer <PAT>`、`Accept: application/vnd.github+json`、`X-GitHub-Api-Version: 2022-11-28`，Body `{"ref":"main"}`；成功回 204
    - 工作流程有 concurrency 群組，排程與外部觸發同時來也不會重疊寫入
  - 前端用當日每日營運時刻表（開路線時本來就會載入，取消／增調都算到）與發車紀錄＋即時車輛班次配對：早發＝早 5 分以上；誤點＝遲 5～10 分；脫班＝遲 11～30 分；漏班＝遲超過 30 分或表定後 35 分仍未偵測到發車（紀錄中斷或路線沒有車機回報時不判）
  - 路線頁顯示本方向今日異常（含車牌）；看板彙整監測路線，未載入時刻表的路線可一鍵載入（使用者的 TDX 金鑰），2 分鐘自動更新
- 3D 導航候車中：視角從上車站望向公車來向，要搭的車常駐標籤（在哪站、還有幾站、早/遲、發車早/遲、塞車）；畫出該路線同方向整條路線與各站（不搭的路段淡化）；上車站標「hh:mm上車」（遲紅、早藍、準點綠）；早/遲等每日營運時刻表載入後才顯示，沒載到每 2 分鐘重試
- 方案摘要列「HH:MM 出發（HH:MM 於 站名 上車）」；點各段的路線號碼開該路線資訊並定位到上車站；點「步行約 ? 分 到…」地圖縮放到該段步行路線
- 步行只從下車站直接走到下一個上車站或終點，不經中途站牌；選取方案的步行段在地圖上依 OSM 步行路線（FOSSGIS routed-foot）畫出，查不到時畫直線；會把步行段起訖座標送到該服務，結果在裝置快取 30 天
- 勾選 🚲 YouBike 時，起訖兩端可騎車接駁：每段騎車 ≤ 25 分，且騎車合計不超過旅行時間（出發到抵達）的 1/5；不提供全程騎車方案
- 騎車段優先沿自行車道、公園綠地、河道（OpenStreetMap 資料，`data/green.json`）：兩站連線上靠近這些地方的比例越高，挑站與排序時騎車時間少算最多 30%（顯示的時間不變），卡片標示「🌳 沿自行車道／綠地／河道約 ?%」；選用公車＋YouBike 方案時，地圖以綠線畫出騎車段附近的自行車道

## 使用前：設定 TDX 金鑰

即時資料需要 TDX API 金鑰。網頁不內建金鑰，請自行到 [tdx.transportdata.tw](https://tdx.transportdata.tw/) 免費註冊，在「會員中心 → API 金鑰」取得 Client ID 與 Client Secret，再點網頁左上角的「🔑」貼上。

- 金鑰只存在你自己的瀏覽器（localStorage），不會傳到其他地方。
- 未設定金鑰時，路線圖、站牌、路線站序仍可瀏覽，只是沒有即時資料與時刻表。
- 程式限制每分鐘最多呼叫 3 次 API（兩個頁面共用計數），並快取結果以節省額度。

### 路網更新後的重產流程

`taichung-network.js`（全市站牌與路線站序）更新後，在 repo 根目錄依序執行。後面的步驟會讀前面步驟的輸出，順序不能對調：

1. **道路線形**：`OUT=tools/shape_all.json node tools/probe.js '/v2/Bus/Shape/City/Taichung?$format=JSON'`，再執行 `node tools/mk_shapes.js 3`，輸出 `taichung-shapes.js`。
2. **班表與站間時間**：`node tools/mk_static.js`，輸出 `data/index.json`、`data/r*.json`。站間時間逐條路線查詢，約 390 次，可中斷續跑。要重抓班表時加 `--sched-api`。
3. **站站推估班表**（約每月一次）：`node tools/mk_est.js`，輸出 `est/*.json`。
4. **路線 UID 與英文名稱**：`node tools/mk_ids.js --api`，輸出 `taichung-ids.js`、`data/stops_en.json`。先讀排程快取，缺的才向 TDX 抓 Route／Stop 各 1 次（快取 30 天）。輸出訊息若列出「缺」的子路線，這些路線的公車位置會改用路線名稱查詢。
5. **路線群組（藍線）**：`node tools/mk_groups.js`，輸出 `data/groups.json`。需要第 1 步的線形；藍線 GeoJSON 改了也要重跑。
6. **捷運風格路線圖**（有新增路線或站序變動時）：`node tools/mk_plan.js`，更新 `taichung.html`、`taichung-routes.js`。

需要 TDX 金鑰的步驟（1～4）讀環境變數 `TDX_CLIENT_ID`／`TDX_CLIENT_SECRET`，或 `tdx-key.local.js`。完成後一併上傳產生的檔案。

## 新增 3D 公車塗裝

導航畫面裡，符合 `data/livery.json` 規則的公車顯示成 3D 模型，其餘用公車圖示。新增車款：

1. 準備該車款的側面或斜前方照片。
2. 開 `tools/livery.html`（建議由網站開啟；用本機檔案開啟時按「開啟 livery.json…」選 `data/livery.json`）。
3. 載入照片，右邊點選部位後點照片上對應位置取色，取完自動跳下一個部位；調整車長、保險桿、車頭閃電、車頂箱，看預覽確認。
4. 填塗裝 id、名稱、屬於此車型的車牌（已確認的車），與比對規則（涵蓋還沒確認車牌的車）：路線（可多條，逗號分隔）、車牌正則（例 `^EAL`）、業者名稱（名稱包含即符合）；留空＝不限。
5. 按「下載 livery.json」覆蓋 `data/livery.json`。

比對順序：先查車牌清單（`plates`，任何路線都適用），查不到再比對規則；規則由上往下比對，第一條符合的生效，車牌條件較細的規則要放在同路線的一般規則前面。車身為方塊組成，只表現大塊配色。

## 已知限制
- 未來日時刻表只依 TDX 路線班表的星期設定，未考慮國定假日。
- 約 185 條路線（346 個子路線方向）沒有 TDX 站間旅行時間，中途站沒有時刻表；路徑規劃只在有即時預估時才會使用這些路線。
- 臺中捷運沒有逐站時刻表，各站時刻依官方班距與站間行駛時間推算。
- 金鑰在瀏覽器端使用；若要多人共用同一把金鑰，應改由自己的伺服器代理 API。
